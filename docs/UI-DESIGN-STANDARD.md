# LinkAssist UI 设计标准

维护基线：2026-11-07。适用范围：主窗口、分离终端、通道配置、画布、设置、菜单及其他应用自有 UI。

本文依据当前源码和终端标签栏的实际布局检查整理。“现状”描述已有实现；“规则”约束后续新增或修改；“待统一”记录尚未满足规则的存量差异。本文不代表所有界面、主题和原生窗口均已完成视觉或无障碍验收。

样式事实以 [globals.css](../src/styles/globals.css)、[Tailwind 配置](../tailwind.config.js) 和各组件源码为准。改变公共视觉约定时，应同时更新本文；不要直接编辑自动生成的 [REFERENCE](REFERENCE.md)。

## 1. 设计定位与判断准则

LinkAssist 是高信息密度的桌面通信工作台。现有视觉语言由低饱和表面、细线分区、紧凑工具栏、通道语义色和有限的浮层阴影组成。主要内容保持平直，窗口与浮层通过圆角区分边界，颜色帮助识别对象和状态。

后续设计遵守以下优先级：

1. **操作和数据清晰**：通道归属、收发目标、连接状态、当前窗格和当前标签必须可辨。
2. **空间稳定**：选中、悬停、显示关闭按钮和连接状态变化不应造成整行跳动；操作按钮不能被长名称挤出。
3. **结构连续**：轮廓、分隔线、圆角和连接位置应属于明确的容器，避免重边、断线和多余接缝。
4. **语义一致**：相同动作沿用已有点击行为，相同对象沿用已有配色、字体和状态反馈。
5. **局部复用**：先复用本功能域的公共控件与样式，再考虑提取通用能力。不要为单个页面另造一套主题。

处理冲突时，优先保证交互正确、文字可读和按钮可达，再压缩间距。高信息密度不等于所有文字都使用最小字号。

## 2. 布局骨架与空间归属

### 2.1 主窗口

当前布局关系如下，区域可由用户隐藏、调整宽度或分割：

```text
╭──────────────────── 窗口外框 ─────────────────────╮
│ 通道快捷操作          标题栏 / 全局与窗口操作       │
│ ┌通道栏（road）┐ ┌── 中央工作区 ──┐ ┌─ 画布区 ──┐ │
│ │ 通道列表     │ │ 通道配置       │ │ 表 / 图 /   │ │
│ │              │ │（固定时占位） │ │ 表单 / 脚本 │ │
│ │ 设置入口     │ ├───────────────┤ │             │ │
│ │              │ │ 标签 / 终端   │ │             │ │
│ └──────────────┘ └───────────────┘ └─────────────┘ │
╰───────────────────────────────────────────────────╯
```

`road` 是标题栏、左侧通道栏及工作区间隙使用的结构底色；`surface` 是主要工作表面。左侧与标题栏构成连续的 L 形外部空间；中央区和画布区有各自轮廓。该图表示空间关系，具体控件与隐藏状态以运行时布局为准。

| 项目 | 当前基线 | 后续规则 |
|---|---|---|
| 窗口外框 | 14px 圆角、四边统一 1px 边框、内部 `p-0.5` | 保持根节点背景透明并按物理像素客户端尺寸对齐，避免高分屏非整除缩放裁切底/右 1px 边框或叠加底边重线 |
| 标题栏 | 32px 高；窗口按钮 44×32px | 控件使用 no-drag；只让空白拖动区响应窗口拖动 |
| 通道栏 | 宽度 40–150px；低于 100px 切换折叠表现；图标轨道 40px | 折叠保持图标对齐，名称渐隐/截断，提供完整名称提示 |
| 中央区 | 最小宽度 300px；默认宽度 670px | 用户拖动后的尺寸应保持；弹层开合不应意外改变相邻区宽度 |
| 右侧区 | 当前布局保留最少 48px 的空间 | 这是布局兜底值，不是内容可用宽度；窄区须有对应降级方式 |
| 主工作区外框 | 12px 圆角、细分隔色边框；中央/右区之间留窄间隙；隐藏通道栏且仅显示中央工作区或仅显示画布区时，当前栏左、右、下部延伸至主界面外框，标题栏下方顶边改为直线分隔；全部区域隐藏时主窗口尺寸不变，隐藏主内容区并仅保留右上角三个窗口按钮，整个主窗口作为标题栏响应拖动与右键显示控制菜单 | 维持相邻区域的顶边和底边对齐；单栏贴边时不叠加内层左/右/底边框 |
| 内部滚动 | 根页面不滚动，内容区各自滚动 | flex 子级设置 `min-w-0` / `min-h-0`，让内容收缩而不是撑破窗口 |

最大化时复用 `MainLayout` 的外框偏移与内容补偿逻辑，避免重复叠加圆角、内边距或边框。分离终端继续遵守相同主题、文字和控件规范。

来源：[MainLayout](../src/components/layout/MainLayout.tsx)、[uiStore](../src/stores/uiStore.ts)、[PaneTreeRenderer](../src/components/layout/PaneTreeRenderer.tsx)、[App](../src/App.tsx)。

### 2.2 通道配置：预览与固定

- **预览态**：从通道栏滑出的浮动卡片，连接到选中的可见通道行；允许覆盖工作区，不挤压终端。使用通道色轮廓、半透明背景和局部模糊。
- **固定态**：同一个配置面板占据中央区上方空间，与终端以直线分隔；背景回到 `surface`，取消浮层圆角和阴影，不保留与通道行相连的外观。
- **隐藏态**：不能拦截鼠标或接受键盘焦点。当前实现使用 `aria-hidden` 和 `inert`。
- 预览与固定之间保留控件实例与输入状态；切换布局不应重建表单并清空内容。

来源：[ChannelConfigDrawer](../src/components/layout/ChannelConfigDrawer.tsx)。

## 3. 走线、边界与圆角

“走线”涵盖窗口轮廓、面板分隔线、表单行分隔线、通道连接轮廓和画布边界。

### 3.1 线条语法

| 线条 | 用法 | 规则 |
|---|---|---|
| 普通边框 | `border border-border` | 默认 1 CSS px，不随意加粗 |
| 弱结构线 | `var(--divider-default)` | 用于工作区外框等低干扰分界；与控件边框区分 |
| 悬停/激活边界 | `border-hover` / `border-active` | 增强同一边界的对比度，避免改变盒模型尺寸 |
| 配置/表格行线 | 左右内缩 8px 的细线 | 不贯穿圆角；配置行、表格行末行已有省略规则，表单行遵循自身分组语义 |
| 通道标记 | 通道色、侧边标记、轻底色 | 用于归属/选中，不把普通区域都描成彩色 |
| 拖拽/创建预览 | 画布已有 2px 虚线或高亮轮廓 | 仅在交互期间显示，不固化为常态装饰 |
| 拖动手柄 | 细线或无可见线，扩大命中区域 | `ResizeHandle` 当前命中宽度为 8px；终端分割线同样扩展可抓取区域 |

共边由一个层级负责绘制。画布最大化使用外层框时，内部去掉重复边框；分割线与父边框交汇时检查是否出现 2px 深色接缝。装饰线使用 `pointer-events-none`，不能遮挡按钮或输入。

### 3.2 通道行与预览卡的连接轮廓

此处是应用已有的特定视觉模式，应复用 [channelCardGeometry](../src/components/layout/channelCardGeometry.ts)：

- 卡片半径 12px、通道连接标签半径 7px、内凹连接圆角 8px、通道行上下内缩 2px。
- 连接处由统一几何路径处理；对齐时通道行顶边顺接卡片顶边，底边通过内凹圆角过渡到卡片左边。
- 已连接的通道行右侧开口，不再叠加竖边；连接处不应被工作区裁切，也不应留下阴影形成的竖向接缝。
- 通道行完全可见时才附着；滚动出可见区域、隐藏通道栏或缺少锚点时，应退回独立卡片轮廓。
- SVG 轮廓保持 `stroke-width: 1px` 与 `vector-effect: non-scaling-stroke`，避免几何变换导致描边粗细漂移。

### 3.3 圆角层级

| 场景 | 当前常用半径 |
|---|---|
| 主窗口 | 14px |
| 主区域外框、通道预览卡、常规菜单 | 12px / `rounded-xl` |
| 大对话框、保存命令浮层、Tooltip | 16px / `rounded-2xl` |
| 圆角选择器、菜单项、通道动作按钮 | 8px / `rounded-lg` |
| 普通输入框、部分通道行 | 6px / `rounded-md` |
| 紧凑工具按钮、旧式 panel-card | `rounded-sm`，当前覆盖为 2px |
| 终端标签、固定配置面板 | 平直接合，通常无圆角 |
| 画布元素边框、创建与吸附预览 | 12px / `rounded-xl` 圆润曲线；贴靠接合对齐侧圆角自适应归零 |

不要把所有表面统一套成大圆角卡片。内层圆角服从外层裁切；接入已有表面时可将共边侧圆角归零。

## 4. 配色与主题

### 4.1 颜色唯一入口

颜色通过 `globals.css` 的 CSS 变量定义，通过 `tailwind.config.js` 映射为语义类。新增 UI 必须优先使用这些 Token；不要把下表数值复制成组件内硬编码。

| `surface-tertiary` | 232 237 244 | 17 17 17 | 输入区、设置侧栏等局部层次 |
| `surface-overlay` | 255 255 255 | 34 34 34 | 菜单、浮层 |

### 4.2 归属色与状态色

- 通道类型映射保持固定：BLE → blue，UART/serial → mauve，TCP/UDP → green。
- 通道已连接时图标使用类型色，连接中使用 yellow，可伴随轻微脉冲；错误使用 red；未连接弱化。选中态与连接状态是两个独立维度。
- 终端选中标签沿用绑定通道色；汇总标签用 `ALL`，组合标签用 `MIXED`，配合选择圆点。混合通道色使用现有计算函数，不凭感觉另挑颜色。
- 画布使用 `computeCanvasBorderColor` 的主题感知混色；非激活画布回到中性边界，选中和拖动提高轮廓强度。图表序列色属于数据编码，不等同于通道连接状态。
- 颜色必须辅以图标、文案、选中标记或可访问状态。不能仅靠红/绿区别成功失败或仅靠淡化解释禁用原因。

来源：[LeftPanel](../src/components/layout/LeftPanel.tsx)、[TerminalChannels](../src/components/layout/TerminalChannels.tsx)、[Canvas](../src/components/display/Canvas.tsx)。

### 4.3 主题适配

应用有 light、dark、system、high-contrast、high-contrast-light 五种设置。system 会根据系统主题及对比度偏好选择对应表现；高对比深色同时带有 `.dark` 类。

高对比主题已有独立变量：深色使用黑底、白色主文字与白色默认边框；浅色使用浅底、黑色主文字与黑色默认边框。不要用低透明度覆盖破坏这些边界。`text-muted` / `text-faint` 在普通深色主题很弱，不适合承载唯一的关键状态或必填说明。

Portal 脱离局部容器后，要保留主题语境；例如 `RoundedSelect` 会把 `.light-surface` 传到浮层。主窗口和分离窗口应同步主题。高对比、系统跟随和局部浅色表面均须检查，不能只看默认浅色截图。

## 5. 字体、间距、尺寸与图标

### 5.1 字体与密度

| 内容 | 现有基线 | 使用规则 |
|---|---|---|
| 配置表单、通道名称、常规菜单 | sans，通常 14px / `text-sm` | 适合主要操作与阅读 |
| 紧凑菜单、Tooltip、终端输出 | 通常 12px / `text-xs` | 终端使用 mono；说明保持可读 |
| 终端标签与紧凑配置项 | 11px | 不推广为整页正文尺寸 |
| 小节标签、类型与元信息 | 10px，局部 uppercase / tracking-wider | 仅用于短标识，避免长句或中文正文强制加字距 |
| 选中或重要内容 | medium / semibold | 同一行避免全部加粗；测量宽度需考虑字重变化 |

命令、HEX、UUID、地址及需逐字符对齐的数据优先使用 `font-mono`；普通设置与解释使用 `font-sans`。长名称使用截断并保留完整提示；长错误信息可换行，不把关键原因隐藏在省略号之后。

### 5.2 间距和命中范围

- 以现有 4px 间距步进为基础；紧凑细调使用 2px、6px、10px。优先复用 `gap-1.5`、`gap-2`、`px-2.5`、`p-3` 等已有组合。
- 标准工具按钮 28×28px；表单控件常用 32px 高；通道配置行至少 40px 高；配置主体常用 12px 内边距，大编辑对话框可用 24px。
- `.channel-config-control` 当前宽度为 200px，最大不超过所在行 60%；标签与控件对齐，窄区域需要验证两者不会相互挤压。
- 图标本身较小不等于点击区域也要小。工具栏常用 11–12px 图标放在 28px 按钮内；菜单和表单常用 14–16px 图标。
- 复用 [Icons](../src/components/common/Icons.tsx)：24×24 viewBox、默认 16px、`currentColor`、2 单位描边、圆端点与圆连接。不混用实心装饰图标、Emoji 和不同粗细的图标库。

## 6. 终端标签栏的固定行为

本节包含已确定的交互约定，后续优化必须保留：

1. 标签按名称自适应宽度。当前最小宽度 64px、常规最大宽度 240px；更窄时服从可用宽度与溢出规则。超长文字截断并提供完整名称提示。
2. 内容左右各 10px 内边距，图标、名称、关闭按钮之间使用 6px 间隔。关闭按钮独立占用 16px，不绝对定位到文字上；悬停/键盘焦点显示时不改变宽度。固定标签没有关闭按钮。
3. **“+”直接为左侧当前选中的通道新建终端标签**，允许同一通道有多个标签。不打开选择菜单，也不创建新的底层通道。未选通道时沿用错误提示。
4. **“…”只在标签放不下时出现**，用于选择隐藏标签、打开尚未单独打开的通道，以及新建通道。选择隐藏标签后，该标签应进入可见区域。
5. 从左到右是“可见标签 → + → …（需要时）→ 剩余空白 → 三个固定功能按钮”。“+”和“…”跟在标签尾部，不能右对齐到工具按钮旁。
6. 弹出独立窗口、分割窗格、保存命令三个按钮始终保留位置，不能因为失焦或标签过多被隐藏、滚走。选择固定标签时，弹出操作仍遵守原有固定标签限制。
7. 优先保留当前标签，其余按现有顺序填入；宽度不足时把完整标签收入菜单，避免半个标签露出。极窄区域可以没有可见标签，但仍需保留溢出入口与可容纳的固定操作。
8. 容器缩放、名称变化、字重变化、增加/关闭/拖动标签后重新测量；固定操作区不参与标签滚动。关闭按钮点击不能同时触发标签选择。

来源：[TerminalLeafPane](../src/components/layout/TerminalLeafPane.tsx)、[TerminalTabMenu](../src/components/layout/TerminalTabMenu.tsx)。最近浏览器检查覆盖 150、320、640、1000px 的终端容器；这些尺寸是回归样例，不是所有布局的断点，也不表示原生 WebView 已验证。

## 7. 控件、状态与反馈

优先复用 `.btn-icon`、`.btn-channel-action`、`.input-base`、`.channel-config-row` 与 [RoundedSelect](../src/components/common/RoundedSelect.tsx)。已有组件只负责其当前能力，复用前仍须核对目标场景的定位和键盘行为。

| 状态 | 新增/修改 UI 的要求 |
|---|---|
| 默认 | 中性表面、语义文字、轻边框；动作名称明确 |
| 悬停 | 使用 `--layer-hover` 或该域已有选中层；提升图标/文字对比，不改变布局 |
| 已选中 | 使用轻底色、语义色/轮廓、字重或标记；与暂时悬停区分 |
| 键盘焦点 | 必须有 `focus-visible` 反馈；不能只有 `outline-none` |
| 禁用 | 原生 `disabled` 或等价行为与可访问状态；只降低透明度不算禁用 |
| 执行中 | 保留动作区域和尺寸，提示正在执行；防止重复提交造成重复操作 |
| 错误/警告 | 使用 red/yellow 语义色及具体原因；可恢复错误给出可执行的下一步 |
| 空状态 | 简短说明当前为空及下一步入口；弱提示不能挡住内容交互 |

表单标签与输入关联，单位靠近数值，placeholder 不替代标签。单选、多选、开关分别使用正确语义。重要状态应留在相应内容区；[Toast](../src/components/common/ToastContainer.tsx) 用于短反馈，不作为唯一错误记录。删除、断开、停止等动作要区分语义，避免仅用同一个叉号表达所有行为。

## 8. 弹窗、菜单、抽屉与 Tooltip

### 8.1 先选择正确的表面

| 类型 | 使用场景 | 表现与关闭 |
|---|---|---|
| 锚点菜单/右键菜单 | 短动作列表、通道选择、标签溢出、保存命令 | 靠近触发点；不压暗背景；外点、Esc、完成选择关闭 |
| 选择器下拉 | 单个字段的值选择 | 与触发控件关联，通常同宽；列表内部滚动，选中项清晰 |
| 通道预览抽屉 | 临时查看/修改当前通道 | 连接到通道行，不压暗整个工作台；可固定到中央区 |
| 模态对话框 | 设置、复杂画布编辑、需要集中完成的任务 | 居中、遮罩、受限宽高、内容滚动；有明确关闭路径 |
| Tooltip | 图标解释、被截断名称、补充信息 | 无交互、`pointer-events-none`，不承载必要操作 |
| Toast | 短时结果通知 | 不阻塞工作区；颜色与图标表达级别，允许关闭 |

名字包含 `Dialog` 不代表必须有暗色遮罩。例如 [SavedCommandsDialog](../src/components/layout/SavedCommandsDialog.tsx) 当前是按钮锚定浮层，点击外部关闭，背景保持原亮度。

### 8.2 定位、尺寸与视觉

- 菜单使用 `surface-overlay`（部分选择器沿用 `surface`）、1px 边框、12–16px 圆角及有限阴影；菜单项使用 8px 圆角。避免给每一项单独加阴影。
- 内容型菜单按内容宽度展开并设视口上限；字段选择器通常与触发器同宽。菜单过长时内部滚动，不能整块越过屏幕边缘。
- 以锚点或指针坐标计算位置，预留约 8px 安全边距；空间不足时翻转或夹紧。现有部分夹紧菜单采用 4px 边距，这是兼容实现，不应复制固定坐标到新组件。
- 窗口变化、容器滚动、菜单内容变化后重新定位或主动关闭；不能让浮层停留在过期的锚点位置。
- 使用 Portal 避开父容器 `overflow-hidden`；嵌套菜单应标明归属，参考 `data-portal-owner`，避免父抽屉把点击子菜单误判为外点。
- 模态遮罩沿用 `.main-dialog-backdrop`：浅色 `bg-black/40`、深色 `bg-black/60`，轻模糊；窗口化时沿 14px 外框裁切。
- 大对话框沿用 16px 圆角、细边框、`surface`、较强阴影；设置窗口当前上限 900×640px，画布编辑当前最大宽度 52rem，两者高度都受 `100vh - 4rem` 约束。此为各自基线，不是所有弹窗统一尺寸。
- 标题/操作区尽量保持可见，长内容在内部滚动；避免表单增长把关闭或提交按钮推出视口。

### 设置子页的分组样式

- 各设置子页左上角的页面标题使用 20px、bold 字重和 `text-primary`，与卡片分组标题区分层级。

- 内容底色使用 `surface-secondary`；浅色主题的分组卡片与内容区使用相同底色，深色主题的分组卡片使用 `surface-overlay`。卡片保留 16px 圆角和 1px 语义边框，分组标题位于卡片外，使用 14px 半粗字重。
- 卡片左右内边距 16px，相邻设置项之间使用内缩分隔线，首尾不另画横线。常规行最小高度 60px、上下内边距 12px。
- 左侧为 13px 半粗标题和 12px 次级说明，右侧放紧凑的圆角按钮、带边框选择器或开关；说明使用 `text-secondary`，不依赖低对比的 muted 色。
- 内容宽度不足 420px 时允许控件换到下一行并保持右对齐；设置侧栏在窄窗口收窄，内容独立滚动。MCP 脚本等复合内容允许多行展示。

### 8.3 键盘与层级规则

后续新增或改动弹层需满足：

- 明确的可访问名称；模态使用 `role="dialog"` 与 `aria-modal="true"`，普通浮层不冒充模态。
- 打开后焦点进入适当控件；真正的模态限制焦点在内部；关闭后将焦点返回仍然存在的触发器。
- Esc 优先关闭最内层浮层，不应同时关闭父窗口；处理嵌套事件时检查并设置 `defaultPrevented`。
- 菜单支持与其语义一致的键盘操作，普通按钮支持 Enter/Space；新组件不能只支持鼠标或把右键作为唯一入口。
- 隐藏层不拦截输入；关闭后清理监听与定位观察器；从内部拖动到遮罩释放不能误判为外部点击。

**当前 z-index 并未统一 Token 化**：设置/画布编辑/保存命令浮层常见 9000，终端选择浮层使用 9998/9999，圆角选择器 10000，部分 Tooltip 10010，全局 Tooltip 99999，Toast 100；工作区内部还有局部层叠与拖拽预览层级。数值只能在对应 stacking context 内解释。

新代码先确定“内容 < 局部预览 < 模态 < 模态内菜单 < 对应提示”的实际覆盖关系，再复用所属域层级；不要简单增加一个更大的数。层级统一属于后续独立重构，本次未新增全局层级系统。

## 9. 画布、表格、图表与脚本区域

- 画布主体延续平直工作表面，外框使用 12px / `rounded-xl` 圆润曲线，并在多画布贴靠拼接（左右并排、上下层叠、网格对齐）时共边侧圆角自适应归零保持平直接合，消除缝隙凹角；选择、激活、拖动通过已有边框强度和阴影区分。最大化画布复用外层区域边框，避免双重圆角和边线。
- 表格/表单使用行对齐与内缩分隔线，高频数据不要逐条触发全局 Toast 或明显入场动画。
- 图表坐标轴与网格复用 [adapters/theme.ts](../src/components/display/adapters/theme.ts) 的主题逻辑；数据线需要与网格可区分，用户选择的序列颜色仍保留其数据含义。
- 缩放、平移、选择框、吸附提示和滚动条属于画布坐标系统；改外框或工具条时验证世界坐标/显示坐标转换和裁切，不单靠截图判断拖动正确。
- 图标工具条、菜单和表单沿用相同 Token。脚本自行生成的控件仍应遵守布局、颜色与反馈约定。
- Script Canvas 需求遵守根 [AGENTS.md](../AGENTS.md) 的 script-first 规则：现有脚本能力足够时修改脚本；能力不足时先解释缺口及通用扩展方案，获得明确批准后再改应用源码。

## 10. 动效与性能

常规悬停/颜色反馈约 100–150ms；菜单淡入约 150ms；通道面板展开/固定过渡约 200–360ms。现有几何变换还带独立的 morph 生命周期，修改时要同步 CSS 与组件时序。

- 动效用于解释出现、消失和空间迁移；连接中脉冲用于过程状态，不作常态装饰。
- 拖动/缩放时保持直接跟手；已有通道抽屉会在 resize 时关闭过渡。
- 优先限定 `color`、`opacity`、`transform` 等属性。不要为新的数据密集列表无差别添加 `transition-all`。
- 新增运动效果提供 `prefers-reduced-motion` 降级。现有抽屉与窗口入场已有处理，通用旧动画还需逐项核查。
- 阴影主要用于浮层、画布选中或拖动；主工作区避免多层重阴影。模糊仅用于确有层次意义的浮动表面，不用于大面积高速更新内容。

## 11. 当前待统一项

以下是源码中可见的差异；列出它们是为避免后续复制，并不表示本次已修改对应行为。

| 差异 | 证据/例子 | 后续处理原则 |
|---|---|---|
| 局部硬编码调色 | `LeftPanel`、`CanvasEditDialog` 的部分 red 类；画布滚动条的 slate 类 | 触及这些控件时按语义迁移到 Token，并核查浅/深/高对比主题 |
| 未定义的颜色类 | `CanvasChart` 选择区域使用 `accent-primary`，主题配置没有该键 | 不复制该写法；单独修正为明确语义色并验证选择框 |
| 混色算法不同 | 标题栏快捷按钮有独立 RGB 算法；终端和画布各有混色实现 | 复用本域函数；跨域统一时专门审查视觉与主题影响 |
| 弹层定位能力不齐 | `SavedCommandsDialog` 有上下择位；`RoundedSelect` 当前主要按下方锚定定位 | 复用外观时不要假定已具备所有边缘翻转能力 |
| 键盘/模态能力不齐 | 设置框已有模态语义；画布编辑容器、多个菜单尚未形成统一焦点管理 | 按第 8 节逐个补齐，不宣称已全局满足 |
| z-index 分散 | 各域有不同 Portal 数值和 stacking context | 不以数值大小代替层级设计；后续集中治理 |
| 圆角和基础控件有历史差异 | `input-base`、`select-base`、`RoundedSelect` 和旧 panel-card | 优先当前所在域的规范，不为局部任务顺带全局替换 |
| 低对比辅助文字与动作提示 | 深色 `text-faint` 等较弱；部分操作依赖 hover/右键 | 关键状态补充可读文本与键盘路径；对比度需实际测量，本文不宣称达标 |

## 13. 实现导航

### 远程工作区

- Remote 位于设置的 Advanced 分组、MCP 下方，内容直接显示在设置子页。后台配对监听独立于设置页保持运行；配对请求可弹出批准对话框。
- 远程设置及批准对话框不得挂在标题栏拖动处理器下；Portal 内容需阻止鼠标事件冒泡到拖窗处理器，保证复选框、文本输入和选择操作正常。
- 配对授权弹层必须显示设备名和公钥，键盘焦点留在弹层，关闭后返回入口。
- 控制端在主窗口显示被控端的布局，标题栏只显示绿色被控设备名称；被控端显示蓝色控制设备名称，设置中的 Controlled by 同样使用蓝色，Connected to 保持绿色。点击标题栏设备名先确认再断开。断开后恢复控制端原先的工作区。
- Remote 子页分为上下两个全宽分组：Local access 与 Remote connection。Local access 内以横线分隔 Allow remote、配对码、免本机确认三块；后两块在开启远程访问后显示。配对码无边框，聚焦后也不显示外框，点击（包括重复点击）及键盘聚焦均全选；后方同行放剩余有效时间、复制/刷新图标；下一行为持久化说明与滑动开关。持久化、免确认与 Allow remote 复用同样的蓝色滑动开关；免确认与 Devices list 使用与 Pairing code 一致的 13px 半粗主文字。Remote connection 内 Peer code 标签与输入框左对齐，当前连接、Recent devices 与 Devices list 集中在此卡片内。连接输入框与 Connect、Reconnect、Revoke 等操作按钮统一为 28px 高，按钮与设备名称使用 12px 字号；Connect、Revoke 使用无边框、无背景色按钮（悬停也保持透明），Peer code 输入框背景透明，聚焦时只高亮原有边框，不叠加 outline 或 ring。空间不足时输入框可横向查看完整配对码。
- Remote 操作期间保留控件颜色、透明度和焦点，以 `aria-busy` / `aria-disabled` 表达忙碌并通过同步请求锁阻止重复操作；避免整页按钮禁用/恢复造成明暗闪烁。连接等待期间保留取消入口。
- 设置 Controls 分组顺序为 Channel、Terminal、Canvas；接收显示选项位于 Terminal → Display。Interface 的主题分组名称为 Theme。
- 主窗口未保存关闭偏好时，每次关闭使用模态对话框选择退出或隐藏到托盘；勾选 Always 才记住选择并在后续关闭时直接执行，取消不保存。设置 Close button 的 Ask every time 可恢复询问。
- 远程与本地复用同一套通道菜单、UART/TCP/BLE 配置卡片、终端和画布组件。新建通道后选中并打开原有配置卡片；字段沿用本地自动保存逻辑，连接前等待配置同步完成。远程不新增独立发送栏或“保存到远端”步骤。
- 画布的新建、编辑、删除、分组、拖动和缩放沿用本地入口；表格、图表、表单及脚本的显示控件共享实现。远程只转发操作并呈现被控端数据，不在控制端再次启动脚本或生命周期运行时。
- 工作区编辑检查被控端布局与配置版本；快照不覆盖正在输入的字段，冲突时刷新并提示重试。终端按标签同步记录，清屏不会被 ALL 汇总记录重新填充。
- 文件路径属于当前工作区所在电脑。远程浏览脚本、协议或目录时使用远端文件选择弹层，支持路径输入、目录导航、取消、Esc 和焦点返回；不得弹出控制端本机文件选择器。
- 表面、边界、文字和焦点使用已有主题 token；工作区跟随被控端主题设置。窗口缩窄时由内容区滚动，不能让根页面溢出。
